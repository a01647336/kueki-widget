1 Contexto y Problema

Kueski es una plataforma de financiamiento digital que permite a sus usuarios pagar en comercios afiliados de forma flexible mediante cuotas quincenales sin intereses. Uno de los retos clave del negocio es la baja recurrencia de uso: los usuarios recurren al servicio solo en situaciones de urgencia y despues lo olvidan.

Este proyecto propone atacar ese problema con tres palancas de valor:

  • Mas transacciones — recordatorios contextuales que aparecen en el momento exacto de la compra, cuando el usuario tiene items en el carrito.
  • Menos friccion — simulacion de planes de pago sin salir del sitio de e-commerce.
  • Mas recurrencia — sistema de gamificacion (Score Coach) que premia volver a usar Kueski con puntos, niveles y logros.
Sitios compatibles: Amazon, Mercado Libre, Liverpool, Coppel y Elektra (todos en dominio .com.mx). El widget se activa automaticamente al detectar cualquiera de estos sitios.

Nota: este es un proyecto academico con fines de simulacion. No usa datos reales de Kueski ni esta afiliado a la empresa. No publicado en la Chrome Web Store.

2 Objetivo del Proyecto

Disenar y construir un widget funcional de Google Chrome que, al ser instalado por un usuario, genere mas transacciones para Kueski influyendo positivamente en el comportamiento de compra durante la navegacion en sitios de e-commerce.

Requisitos del brief original (Kueski, enero 2026):

  • Widget funcional de Chrome (Manifest V3)
  • Backend con informacion dinamica (API REST)
  • Persistencia de datos mediante base de datos relacional
  • Propuesta clara de valor de negocio
3 Arquitectura del Sistema
Extension de Chrome (Plasmo + React 18 + TypeScript) | Content Script (kueski.tsx) inyectado en sitios compatibles | Shadow DOM — estilos del widget aislados del sitio anfitrión | MutationObserver — detecta cambios en el carrito en tiempo real | @plasmohq/storage — chrome.storage.local con fallback a localStorage | | HTTPS / Bearer JWT / timeout 8 s (offline fallback) | API REST (Express 4 + Node.js, desplegado en Render) | 20 endpoints: auth, usuario, deals, compras, calendario de pagos, health | JWT HS256 para autenticacion sin estado | Reglas de elegibilidad y calculo de planes en servidor | Base de Datos (PostgreSQL en Aiven, plan gratuito) 3 tablas: users, purchases, deals 5 usuarios semilla con distintos niveles y estados

Flujo principal de uso

  1. El usuario instala la extension en Chrome desde chrome://extensions.
  2. Al navegar a un sitio compatible, Plasmo inyecta el content script.
  3. PriceDetector arranca un MutationObserver que lee el DOM con selectores especificos por tienda (debounce 500 ms).
  4. El widget se monta dentro de un Shadow DOM como panel flotante (esquina inferior derecha).
  5. Si el usuario no tiene sesion, el widget muestra la pantalla de beneficios con CTA de login.
  6. Tras autenticarse, el widget detecta el carrito y ofrece simular el pago con Kueski Pay.
  7. El usuario selecciona un plan quincenal y confirma; la compra se registra en el backend.
4 Funciones y Caracteristicas Principales
Funcion Descripcion
Smart Reminder Detecta en tiempo real si el usuario tiene items en el carrito del sitio actual y muestra un banner contextual con el monto total y un boton para simular el pago. Incluye alerta de vencimiento de pago (azul si faltan 7+ dias, ambar si faltan 3 o menos).
Recordatorios de Pago Panel accesible desde el icono de campana en el header del widget (solo con sesion activa). Lista todas las quincenas pendientes con sitio, monto, fecha de vencimiento y boton de pago simulado. Al pagar, el credito disponible se restaura y el proximo pago se recalcula en tiempo real sin re-login. El badge sobre la campana muestra cuantos pagos hay pendientes. Funciona offline usando los datos locales como fallback.
Simulador de Pagos Calcula planes de pago quincenales personalizados segun el nivel y credito disponible del usuario: de 2 a 12 cuotas sin intereses. Muestra el cashback que se ganara. Incluye flujo de confirmacion en dos pasos y validacion de elegibilidad (credito insuficiente, pago vencido, monto menor a $50, demasiadas compras activas). Tras confirmar, el credito disponible se actualiza de forma optimista y se sincroniza con el backend.
Score Coach Sistema de gamificacion con 4 niveles progresivos. Otorga puntos por compra, pago puntual, racha de 30 dias y referidos. Los logros muestran su progreso real con barra animada (ej. "Usa Kueski Pay 3 veces" muestra 1/3, 2/3, etc.) y se completan automaticamente al cumplir la condicion. El logro de pago puntual se desbloquea al pagar la primera quincena; el de referido tiene un boton de accion directa. Cada nivel desbloquea mayor tasa de cashback y limite de credito.
Buscador de Deals Muestra ofertas promocionales activas del backend. La tarjeta de oferta activa usa colores de marca fijos por tienda (definidos en el frontend) para garantizar legibilidad inmediata sin depender del campo de color del backend. Las tarjetas son interactivas y abren el sitio de la oferta en una pestana nueva.
Perfil de Usuario Muestra nombre, nivel actual, credito disponible y limite, fecha y monto del proximo pago derivado del calendario de pagos activos, tasa de cashback por nivel y historial de compras. El credito disponible y el proximo pago se actualizan en vivo tras cada compra o pago de quincena.
Autenticacion Login con usuario y contrasena. Contrasenas almacenadas con bcryptjs (10 rondas). Sesion persistida en chrome.storage.local con fallback a localStorage. Renovacion de token via refresh-token endpoint.
Deteccion de Carrito MutationObserver con selectores CSS especificos para cada tienda. Funciona en SPAs interceptando history.pushState (Mercado Libre). Actualizacion con debounce de 500 ms para evitar re-renders excesivos.
Modo Offline Si el servidor no responde en 8 segundos, el widget continua funcionando con datos locales (localStorage). El calculo de planes usa la misma logica que el backend, replicada en el frontend. No se muestran errores de red al usuario.
Pantalla de Beneficios Vista de onboarding que explica el valor del widget a usuarios no autenticados: simulacion de pagos, cashback, notificaciones de deals y Score Coach. Incluye CTA de login y enlace al sitio real de Kueski para registro.

7 Base de Datos

PostgreSQL alojado en Aiven (plan gratuito). Tres tablas principales inicializadas al arrancar el servidor.

TablaColumnas claveDescripcion
users id, username, password_hash, name, level, credit_limit, available_credit, cashback_rate, score_points, next_payment_date, next_payment_amount, achievements (JSON), disabled_sites (JSON), notif_deals, notif_reminders, subscriptions (JSON) Perfil completo del usuario. Arrays complejos almacenados como TEXT JSON para simplicidad sin ORM.
purchases id, user_id (FK), site, amount, plan (num. cuotas), payment_per_period, cashback, date, status, installments_paid Registro de compras realizadas con Kueski Pay. Estado puede ser activo, pagado o vencido. El campo installments_paid permite derivar el calendario de pagos: el proximo vencimiento se calcula como fecha_compra + 15*(installments_paid+1) dias.
deals id, site, title, description, discount, tag, color, active Promociones configuradas por tienda. El flag active permite activar/desactivar sin borrar.
